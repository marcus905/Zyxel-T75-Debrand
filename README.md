# Zyxel T75 Debrand

Experimental tooling and reverse-engineering notes for reversible family conversion of the Zyxel EX7501-B0 / Odido T75 between the Odido `ACDA` firmware family and generic Zyxel `ACHN` firmware.

The project deliberately separates **family conversion** from ordinary firmware upgrades. Once a device is running the desired family, normal upgrades should be performed by that firmware's own updater.

## Current status

The converter is built from offline analysis of complete stock and Odido NAND dumps plus public Zyxel firmware packages. An **Odido T75 -> generic Zyxel V5.18(ACHN.2.1)C0 conversion has now completed successfully on hardware**, including the destination U-Boot one-shot reset, generic `rootfs2` boot, `zydefault` mount, configuration initialization, Wi-Fi bring-up, web UI, a normal second boot, and a generic factory reset followed by another successful boot. Reverse conversion and additional-device testing remain experimental. Keep UART attached and retain a verified full ECC-corrected logical NAND backup off-device.

## Repository layout

- `device/` — shell code intended to run on the router from USB/root shell.
- `device/lib/` — staging, metadata, loader-build, verification, backup and post-boot helpers.
- `tools/` — PC-side source-pack normalizer and loader-template auditor.
- `templates/` — anonymized generic/Odido loader templates plus metadata and provenance notes.
- [`docs/`](docs/README.md) — guided documentation index covering access, Source Packs, conversion, architecture, recovery, and validation.

## Conversion flow

```text
inspect current device
        ↓
backup current loader/slot/shared state (+ optional full NAND)
        ↓
normalize destination firmware/source into a Source Pack
        ↓
derive inactive slot from metadata + running rootfs
        ↓
stage destination slot and read-back verify
        ↓
build personalized destination-family loader/NVRAM
        ↓
commit metadata while keeping both firmware slots valid
        ↓
write/read-back verify 2 MiB loader
        ↓
reboot
        ↓
destination U-Boot one-shot removes cross-family shared state
        ↓
destination Linux recreates native shared state
        ↓
postcheck
```

Starting from stock Odido firmware? See [docs/ODIDO_ACCESS.md](docs/ODIDO_ACCESS.md) first to obtain the required root SSH shell. Build the destination firmware material as described in [docs/SOURCE_PACK.md](docs/SOURCE_PACK.md), then use [docs/HOWTO.md](docs/HOWTO.md) for the field-tested end-to-end conversion procedure. [docs/USAGE.md](docs/USAGE.md) is the concise command reference, and [docs/README.md](docs/README.md) links the complete documentation set.

## Artifact separation

The repository intentionally does **not** contain full firmware payloads, NAND/device backups, or device credentials. It does include the two anonymized 2 MiB family loader templates used by the converter:

- `templates/loader-generic.bin.gz`
- `templates/loader-odido.bin.gz`

For a conversion, provide a destination firmware/source pack separately; backups/work directories are generated locally by `device/t75.sh`.

`tools/t75_sourcepack.py` anonymizes any loader extracted from a logical device dump before it is reused as a source-pack template. The original exact backup is never modified.

## Important properties

- Target slot is **never hard-coded**. It is calculated from validated metadata and cross-checked against the running `rootfsN`.
- Public firmware files remain separate from this repository.
- Exact device backups remain private recovery artifacts.
- Reusable loader templates/source packs are anonymized.
- Device identity and credentials are read from the current router and injected only when building the final destination loader.
- `EngDebugFlag` can be preserved, forced to `00`, or forced to `01`.
- Shared volumes are backed up before conversion and regenerated by the destination family rather than carried across families.

## Disclaimer

This software writes bootloader/NAND state and can brick hardware if the assumptions do not match the target device. Review the scripts and documentation, keep UART recovery available, and retain a verified ECC-corrected logical backup before testing.
